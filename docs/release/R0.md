## Probe-Builds (amd64, 8 Kerne)

`packaging/build-components.sh` baut alle Komponenten der
`packaging/components.lock` in etwa 2 Minuten pro Ziel, bei vorhandenem
Download-Cache. Der ganze Paketbau (`packaging/build-deb.sh`) dauert
2–2,5 Minuten pro Ziel.

| Ergebnis | Größe |
|---|---|
| `/usr/lib/pluto-tx` (Libs, lpcnet_demo, js8ref, OOT-Python) | 53 MB (Ubuntu), 57 MB (Debian) |
| `/usr/share/pluto-tx/js8/jsc.json` | 11 MB |
| `.deb` | 28,5 MB (Ubuntu), 27,5 MB (Debian) |

**Der RADE-Build braucht Netz:**
- Er lädt den Opus-Snapshot (5,4 MB zip).
- Opus' `autogen.sh` lädt dann das Modell `opus_data-4ed9445b….tar.gz`
  (176 MB).
- Beides liegt im Cache `packaging/.cache/<ziel>/downloads`.
- Das Modell prüft Opus selbst per SHA-256.
- Im Paket steckt nur das Ergebnis, weil die Gewichte in `librade.so`
  einkompiliert sind.

**gr-m17 — HALT, Entscheidung des Betreibers nötig:**
- Die Top-Level-`LICENSE` von gr-m17 und die `LICENSE` des Submoduls
  `libm17` enthalten den **GPL-2.0-Text ohne Versionsklausel**.
- Die gr-m17-Quellen selbst (Blöcke, Bindings, CMake) tragen
  `SPDX-License-Identifier: GPL-3.0-or-later`.
- Die libm17-Quellen haben **keine** Lizenz-Header.

Ohne Versionsangabe erlaubt GPLv2 §9 die Wahl jeder GPL-Version. Ob das
Mitliefern des v2-Textes schon eine Versionsangabe ist, ist aber nicht
eindeutig. Vor einer Veröffentlichung muss das geklärt werden, am besten
per Rückfrage beim M17-Projekt. Die lokal gebauten Pakete enthalten gr-m17;
`debian/copyright` benennt die offene Frage.
